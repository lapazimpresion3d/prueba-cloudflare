# 51.5.1 — Integridad local POS/caja/inventario

Diario de solicitudes opcional para compatibilidad, máximo 500 operaciones, integrado al único guardado POS v2. Venta, cancelación, movimiento y cierre admiten ID estable y comparación de contenido; reintento devuelve registro vigente, no repite efecto. Permisos revalidados antes de consultar reintento. UI POS y caja genera ID por solicitud y conserva durante fallo en la misma página; no persiste el ID pendiente tras recarga. Cancelación UI conserva flujo anterior, API local admite ID. No modifica descuentos existentes (0–100 con permiso), apertura ni ajustes de inventario manuales. Pruebas de reintentos y fallo antes de escritura. No garantiza atomicidad entre pestañas, manipulación de storage, concurrencia D1 ni recuperación de respuesta perdida tras recarga. No rutas privadas, migraciones ni cobros. Pendiente conciliación anticipos, libro privado y auditoría financiera más amplia.
