# 52.3.1.2 — Generación de invitaciones seguras
Servicio interno emitirInvitacion(r,id): POST HTTPS, mismo Origin, sesión central reciente revalidada en SQL, operador original activo. Solo solicitudes pendientes vigentes preparadas con prueba de prospecto a partir de esta migración. Se registra procedencia en el mismo batch de prepararProspecto; no se infiere retrospectivamente de datos de identidad. Altas anteriores a 0020 deben prepararse de nuevo por vía verificada antes de emitir invitación (sin migración automática). Token aleatorio de 256 bits, devuelto una sola vez, SHA-256 persistido, vence como máximo en 24 horas y nunca después del alta. Restricción única por alta, emisión y auditoría atómicas; sin correo, secretos o token en auditoría. No hay entrega automática; canal verificado y respuesta sin caché/logs serán responsabilidad de futura ruta. Se bloquea aceptar histórico para altas con procedencia prospecto; no se cambia la API histórica para casos antiguos, no exponerla. Aceptación OIDC y consumo atómico de invitación quedan para 52.3.1.3; renovación y cancelación para 52.3.1.4 (columnas reservadas, sin servicio aún). No se crean empresas, contratos ni sesiones por emitir. Migración 0020 exclusivamente COMMERCE_DB, sin aplicación remota. Pruebas SQLite simuladas; D1 remoto pendiente.
