# 52.3.1.3 — Aceptación mediante OIDC
Propósito alta separado en huella OIDC, comercial exclusivamente, limitador obligatorio. iniciarAceptacion recibe token por POST mismo origen, guarda hash en estado OIDC del servidor (0021), comprueba vigencia, alta pendiente, operador activo y propietario no desactivado. No token en URL del proveedor. Callback GET consume estado con cookie, PKCE y nonce; obtiene identidad firmada y hash de la fila consumida, nunca del navegador. Reutiliza núcleo de creación de empresa con comprobación SQL de identidad exacta y de invitación vigente; batch crea empresa, sucursal, roles, propietario, perfil, auditoría y consume invitación. Rollback conjunto. No sesión ni contrato automático. Reintento tras fallo requiere iniciar OIDC nuevo. No rutas activas, secretos reales ni migraciones remotas. Pendientes cancelación/renovación, deduplicación, primer acceso y pruebas remotas.
