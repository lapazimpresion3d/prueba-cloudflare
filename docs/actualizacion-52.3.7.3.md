# 52.3.7.3 — Reactivación y recuperación del servicio
Servicio central interno POST reactivar, revisión optimista, motivo obligatorio, sesión reciente y origen. Verifica alta aceptada, empresa activa, vigencia, propietario activo, cupos, selección previa no vacía, compatibilidad, disponibilidad y dependencias de módulos. Conserva plan, versión, fechas, selección, datos y permisos. SQL revalida evidencia de contrato/activación y requisitos; migración 0044 refuerza requisitos estructurales y corte por empresa/usuario al reactivar para invalidar también sesiones creadas durante suspensión. No revoca sesión global. Nueva autenticación posterior al corte necesaria. Consulta distingue vigencia efectiva de estado persistido. Pruebas OIDC/SQLite de rechazo de revisión antigua, operador no autorizado, disponibilidad técnica insuficiente, recuperación con nueva sesión, rechazo de sesiones anteriores/durante suspensión y conservación de otro comercio. No exige entrega comercial para recuperar configuración previa; no autoriza publicación ni módulos adicionales. No renueva contratos vencidos. Pendiente auditoría de concurrencia de todas las rutas, pruebas de límites y vigencia en integración dedicada, D1 remoto y UI. No despliegue ni migración remota. Siguiente 52.3.7.4 cancelación y baja.
