# 52.3.7.1 — Estados y transiciones comerciales
Núcleo puro de estados persistentes prueba/activa/suspendida/cancelada y derivados sin_contratar/programada/vencida. Suspensión preserva plan, versión, fechas y selección; reactivación restaura exactamente el estado anterior y solo dentro de vigencia, no renueva ni convierte prueba en activa; cancelación terminal. Migración 0042: historial inmutable de transición ligado a contrato inicial, revisión, motivo, operador y fecha; trigger aplica transición y auditoría atómicamente, preserva guard de cambios contractuales. Consulta central con sesión real, sin rutas HTTP ni métodos de escritura expuestos: la siguiente fase deberá integrar corte de acceso selectivo antes de habilitar suspensión, y las fases posteriores autorizar reactivación y cancelación. El SQL es base interna, no una autorización de uso manual. No se altera empresa.activa, usuarios, membresías, datos ni tarifas. Pruebas del modelo y consulta en fixture OIDC, rechazo de UPDATE directo. Sin D1 remoto ni producción. Pendiente prueba integral de transiciones positivas y aislamiento de sesiones.
