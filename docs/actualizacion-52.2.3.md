# 52.2.3 — Acceso central separado
Módulo interno acceso-central.mjs: OIDC central con ACR configurado, operador registrado activo por emisor+sujeto, cookie __Host-lapaz-central separada, hash SHA-256, duración 60 minutos, inactividad 10 minutos, una sesión por operador mediante rotación atómica en batch. POST requiere mismo origen y sesión creada hace menos de 5 minutos; GET permite lectura mientras vigente. Reautenticación mediante nuevo flujo OIDC y rotación de sesión; no es prueba de nuevo factor físico ni garantiza auth_time posterior al anterior (proveedor debe garantizar ACR y frescura). La ventana de cinco minutos desde creación se suma a la ventana del token de 52.2; no equivale a cinco minutos desde MFA real. Baja del operador revoca sesiones mediante trigger. Cierre individual; no hay UI ni gestión remota de dispositivos, no hay operador real aprovisionado.
El callback autenticarCentral es compatible con administrador-central.mjs, pero no conectado a rutas ni se modifica servicio histórico; el guard SQL de éste aún solo comprueba operador activo, no sesión y frescura dentro de cada escritura. Antes de producción integrar guard atómico, registrar auditoría de sesiones centrales, limpieza de expiradas, limitar frecuencia OIDC, configurar proveedor y separar clientes OIDC si procede. Cookie temporal OIDC compartida por flujo (una autenticación simultánea por navegador). Migración 0016 solo COMMERCE_DB; no aplicada remotamente. Pruebas SQLite y proveedor simulado. Worker cerrado. No se registran operadores reales ni secretos.
