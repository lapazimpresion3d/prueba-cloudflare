# Corrección de disponibilidad (v0.11.1)
Incidencia reportada: al cambiar disponibilidad de un producto no se reflejó en la página. Se encontraron dos causas potenciales en código, sin identificar aún cuál URL utilizó el propietario.
- Menú original: refrescaba automáticamente solo al cambiar fecha. Ahora consulta al recuperar foco/visibilidad, volver con historial y cada 30 segundos si está visible; evita actualización durante revisión/confirmación de pedido. Conserva API /menu.json, DB y validación de pedido existentes.
- Nueva demostración multicomercio: el botón Salir del panel abría la semilla limpia; ahora vuelve a practica=1. Se añade Ver catálogo editado y enlace separado Ver página original sin cambios. Botón directo Marcar agotado/disponible por elemento. En práctica, producto agotado desaturado, etiqueta y sin botón de agregar. Al restaurar página desde caché de historial, se recarga la copia local.
- La práctica local usa sessionStorage de la misma pestaña/origen; no se publica a otros visitantes ni se mezcla con la demo original. Guardar catálogo sigue siendo explícito para D1, Recuperar catálogo para traer la copia; no se añade sincronización automática remota. No prometer que cambios de una demo actualizan otra.
Pruebas: sintaxis de tres controladores e IDs HTML; edición real en repositorio local JS y DOM simulado (pastor agotado en práctica, sin compra, semilla intacta); ejecución aislada de función de refresco original en el mismo día y bloqueo durante revisión/página oculta. No se confirmó despliegue ni se realizó escritura en D1. Main no modificado.
