# 51.7 — Respaldo selectivo y prevalidación
Servicio interno deshabilitado por defecto, sin ruta ni ejecución programada. Exporta una instantánea de lectura por empresa en COMMERCE_DB con consultas fijas en batch: identidad empresarial, sucursales, roles, permisos, membresías, asignaciones, restricciones, suscripción vigente y libro financiero. IDs de usuarios/actores son datos privados; se excluyen identidad de proveedor, hashes, invitaciones, sesiones y credenciales. No es respaldo completo: no contiene tablas de usuarios, versiones de planes, auditoría, pagos centrales, catálogos privados (aún inexistentes) ni inventarios. No puede reconstruir una empresa por sí solo. Máximo 1000 filas por tabla y 2 MB UTF-8; rechaza exceso, no trunca. JSON versionado y SHA-256 de bytes exactos; prevalidación confirma formato, empresa y conteos, no valida semántica exhaustiva ni autenticidad criptográfica (un atacante puede recalcular hash). No restaura ni escribe. No conectar a HTTP sin autorización, auditoría y cifrado. 
Recuperación integral: seguir docs/respaldo-d1.md, verificar identificador de cada binding DB/DEMO_DB/COMMERCE_DB/PROVIDER_DB independientemente; exportar cada base por separado, cifrar fuera de GitHub, limitar acceso, documentar fecha/commit/migraciones/hash, comprobar restauración a una base nueva aislada, integridad referencial, triggers, conteos y conciliación. Nunca copiar datos privados a demos. Antes de activar una base recuperada invalidar sesiones e invitaciones restauradas y revisar credenciales. No utilizar el snapshot selectivo para restaurar automáticamente permisos o finanzas. RPO/RTO, retención de respaldos, firma autenticada, almacenamiento cifrado, pruebas D1 remotas y restauración selectiva transaccional pendientes. No se ejecutó respaldo ni restauración remotos.
